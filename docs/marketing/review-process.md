# How it works — the whole cycle (explainer)

Correct order: log -> review & decide -> MAKE THE CHANGES (before the meeting)
-> generate report -> meeting & sign-off -> next month checks it worked.
The fix is actioned after review and before the meeting, so changes are in place
by the time the team meets. The app can't make the physical change; it measures
whether it worked. Good as a Facebook post or a "how does it work?" reply.

---

A few people asked how it actually works, so here's the whole thing — start to finish, and what you'd see on screen.

1. Logging a near miss (any staff, any time)
Open the app, tap through a few quick options — what happened, which medicine, where it got caught. No typing it up. Save, done in seconds. No name attached.

2. Reviewing them (the manager, before the meeting)
You see the whole month's near misses in one list. Tap one and it suggests a simple fix in plain English, with three buttons: accept it, reword it, or "no change needed." Work down the list — a couple of seconds each. The app only suggests; you decide every one.

3. Making the changes (still before the meeting)
You action the fixes you've decided — move the shelf, add the warning label, tweak the process. The app can't do this part; it's the real-world bit that's on you. Doing it now means the changes are already in place by the time you meet.

4. Generating the report (one button)
Press generate and the whole month is written up for you in plain English — including the action taken on each near miss. It reads top to bottom like a meeting:
- The month at a glance — how many, up or down on last month
- Did last month's changes work? — each old problem marked gone, less, or still happening
- This month's near misses — each with the action you took
- A sign-off line at the bottom

5. The meeting
You read straight down the report on screen (or print it). Everyone can follow it, because it's plain words, not numbers. You look at the patterns that keep coming back, agree anything bigger as a team, and sign it off.

Then next month, the report tells you whether those changes actually worked — so you're improving on evidence, not guessing.

That's the cycle: log it, decide it, fix it, write it up, meet on it — and next month, check it worked.
