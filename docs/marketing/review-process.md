# How it works — the whole cycle (explainer)

Complete, plain-English walk-through grounded in what you see on screen:
log -> manager reviews & decides each -> generate report -> meeting ->
make the change -> next month's report checks it worked. The app can't make
the physical change; it closes the loop by measuring. Good as a Facebook post
or a "how does it work?" reply.

---

A few people asked how it actually works, so here's the whole thing — start to finish, and what you'd see on screen.

1. Logging a near miss (any staff, any time)
You open the app and tap through a few quick options — what happened, which medicine, where it got caught. No typing it up. Save, and you're done in seconds. Nothing's tied to a name.

2. Reviewing them (the manager, before the meeting)
You see the whole month's near misses in one list. Tap one and it shows a suggested fix in plain English, with three buttons: accept it, reword it, or "no change needed." Work down the list — a couple of seconds each. The app only suggests; you decide every one.

3. Generating the report (one button)
Press generate and, a moment later, the whole month is written up for you in plain English — nothing to format, nothing to add up. It reads top to bottom like a meeting:
- The month at a glance — how many, up or down on last month
- Did last month's changes work? — each old problem marked gone, less, or still happening
- This month's near misses — each with the action you chose
- A sign-off line at the bottom

4. The meeting
You read straight down the report on screen (or print it). Everyone can follow it, because it's plain words, not numbers. You look at what keeps coming back and agree the bigger changes as a team — a name and a date on each.

5. Making the change (this bit's on you)
Someone actually does it — moves the shelf, adds the label, tweaks the process. The app can't do that part. But it closes the loop: next month's report tells you whether it worked, so you're improving on evidence, not guessing.

That's the whole cycle: log it, decide it, write it up, meet on it, fix it — then check it actually worked.
